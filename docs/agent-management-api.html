Architecture & ownership

Management capabilities belong to providers and accounts. A runtime exposes one normalized surface across its composed adapters; a live Agent remains the per-run control and observation object.

Distribution

Discover installed executables, compare releases and run an adapter-declared update recipe.

Profiles

Allocate account roots, launch native login, verify identity and bind a selected root to a process.

Account usage

Fetch normalized account quota metrics and receive provider push updates independently of live runs.

Layer Owns
Core Validated DTOs and DistributionService, ProfileService, AccountUsageService contracts.
Runtime Discovery/cache, release detector execution, updater receipts, registry persistence, profile resolution and result validation.
Provider adapter Native layout, executable classification, update/login commands, environment binding and identity/quota interpretation.
Godview Agents drawer, login tabs, per-provider tab defaults and account-usage polling/backoff. Other hosts supply their own policy.
Scope. This page documents the implemented management API. Run lifecycle and host recovery remain in the Agent API; indexed search is in the Aggregation API.

Read the management surface

Both createAgentRuntime() and createBuiltinAgentRuntime() expose the same management methods. Capability lists identify which composed providers support each family. 

import type { AgentHost } from '@vibecook/puppeteer-core';
import { createBuiltinAgentRuntime } from '@vibecook/puppeteer-builtin-providers';

declare const host: AgentHost; // Supplied by the application.
const runtime = createBuiltinAgentRuntime({ host, defaultCwd: process.cwd() });

const installations = await runtime.inspectInstallations();
const profileProviders = runtime.profileProviders();
const accounts = await runtime.profiles();
const usageProviders = runtime.accountUsageProviders();

for (const account of accounts) {
  if (!usageProviders.some((provider) => provider.id === account.provider)) continue;
  const usage = await runtime.accountUsage(account.provider, account.id);
  if (usage.status === 'available') {
    console.log(account.label, usage.snapshot.metrics);
  }
}

await runtime.dispose();

Management DTOs are exported from @vibecook/puppeteer-core; runtime request/configuration types are exported from @vibecook/puppeteer-runtime. Provider IDs are opaque outside the adapter. A profile uses provider; management requests commonly use providerId.

Installations & releases

Inventory reports what the host can find and which executable the runtime would select. Release checks and updates are separate operations.

AgentRuntime · excerpt

interface AgentRuntime {
  distributionProviders(): readonly DistributionProvider[];
  inspectInstallations(options?: InspectInstallationsOptions): Promise<AgentInstallation[]>;
  checkReleases(options: CheckReleasesOptions): Promise<ReleaseCheckResult>;
  updateInstallation(options: UpdateInstallationOptions): Promise<UpdateReceipt>;
  planUpdate(options: UpdatePlanOptions): Promise<UpdatePlan | DistributionFailure>;
}
Method Contract
distributionProviders() Returns adapter-declared commands, package-manager names and release detectors. This is capability discovery; it does not inspect executables.
inspectInstallations() Optional provider filter. Results are cached per provider until refresh: true. Configured absolute executables, PATH matches, npm roots and Homebrew entries are classified and deduplicated by real path. Unknown providers return an empty inventory.
checkReleases() Compares the active installation with native update-oracle and detector results. network: true enables declared outbound detectors; an available native oracle may run regardless. Failures accompany successful releases in the result.
updateInstallation() Selects the active installation unless executable is supplied. Executes the adapter recipe, then refreshes inventory and returns an update receipt. It does not restart existing agent sessions. An optional onOutput observer receives the updater's output as it arrives, beside the 0600 transcript, so a host can show the vendor's command running; it is opaque text, never parsed, and an observer that throws is reported through onError without stopping the update.
planUpdate() What updateInstallation() would run for an install, without running it: the adapter's recipe for the active installation (or executable), resolved to the argv the runner would execute, so a host can name the command before anyone presses Update. A manual recipe carries no argv. An unknown provider answers unsupported; a provider with no matching installation answers unavailable.

interface UpdateReceipt {
  provider: string;
  status: 'updated' | 'already-current' | 'failed' | 'unsupported';
  recipe?: UpdateRecipe;

  after?: InstalledAgent;
  startedAt: string;
  finishedAt: string;
  exitCode?: number;
  transcriptPath?: string;
  message?: string;
}
Receipt status Current classification
updated Re-inspection returned an installation whose version differs from the previous version, even if the command exit code is nonzero.
already-current The command exited with zero and no version change was observed. after can be absent when re-inspection fails; this status alone does not prove a remote release comparison.
failed No observed version change and command failure, missing target, invalid recipe or failed receipt construction.
unsupported Provider lacks distribution support, or its recipe requires manual instructions.
Updater output. transcriptPath points to an optional file containing opaque updater command output. This file is not an agent conversation transcript or a monitor artifact. Native output is not parsed to derive semantic results.

Profiles & native identity

A managed profile is a persistent native data root bound to a launch. Creating it and authenticating it are separate operations.

AgentRuntime · excerpt

interface AgentRuntime {
  profileProviders(): readonly ProfileProvider[];
  profiles(providerId?: string): Promise<AgentProfile[]>;
  profile(profileId: string): Promise<AgentProfile | undefined>;
  createProfile(options: CreateProfileOptions): Promise<AgentProfile | ProfileFailure>;
  removeProfile(profileId: string): Promise<boolean>;
  startProfileLogin(options: StartProfileLoginOptions): Promise<ProfileLoginResult>;
  verifyProfile(profileId: string): Promise<ProfileIdentity | ProfileFailure>;
  onProfilesChanged(listener: (profiles: AgentProfile[]) => void): () => void;
}
Method Contract
profileProviders() Returns profile descriptors, including support.supported, identity capability and shared native surfaces. Advertising a descriptor does not imply login support.
profiles() Lists registered profiles and synthetic native-default entries for supporting providers with a declared default root. Optional provider filter.
profile() Looks up a registered or synthetic profile by ID; unknown IDs return undefined.
createProfile() Validates a trimmed 1–64 character label, allocates a managed root, optionally initializes native config and persists the registry entry. Returns a profile or typed failure; it does not authenticate the account.
removeProfile() Unregisters a managed profile. Returns false for unknown or native-default profiles. The root and its native data remain on disk.
startProfileLogin() Spawns the provider’s native login in an application host terminal bound to that profile. The returned terminal ID reports launch, not authentication success.
verifyProfile() Reads native identity and attempts to persist it on the profile. A returned identity can have loggedIn: false. Persistence failure is reported through onError while the observed identity is still returned.
onProfilesChanged() Subscribes to profile-list changes; returns an unsubscribe function. Read profiles() for the initial list.

Allocate

Call createProfile({ providerId, label }); render ProfileFailure if returned.

Authenticate

Call startProfileLogin({ profileId }); let the user complete the provider’s own login in the returned terminal.

Verify

When the host observes login completion, call verifyProfile(profileId). Inspect loggedIn and identity metadata.

Bind a run

Pass the profile ID to spawn() or resume(). Persist AgentSessionInfo.profileId beside the opaque continuation.

Native root semantics. Managed roots are immutable because native credential stores may key on their path. Profiles bind process environments; they are not machine-wide account switches or isolation boundaries. sharedSurfaces declares native resources that profiles still share.

Launch binding & observation roots

Applications select a profile by ID. The runtime resolves it and the adapter maps it onto its own native environment and history layout.

AgentRuntime · excerpt

interface AgentRuntime {
  profileBindingEnvironment(profileIds: readonly string[]): Promise<Record<string, string>>;
  profileObservationRoot(profileId: string): Promise<string | undefined>;
}
Method Contract
profileBindingEnvironment() Returns merged environment overrides for terminal seeding. Unknown IDs, duplicate providers or unavailable profile services throw. Supply at most one profile per provider; a native-default profile normally adds no overrides.
profileObservationRoot() Returns the adapter-owned native history layout root. Unknown profile or provider returns undefined. Use this when configuring an external history indexer. 
// runtime is the host's AgentRuntime; account is a selected AgentProfile.
const spawned = await runtime.spawn({
  agent: account.provider,
  cwd: projectDirectory,
  profile: account.id,
});
if ('error' in spawned) throw new Error(spawned.error.message);

// Persist both values if the host will later resume this run.
const saved = {
  continuation: spawned.info.continuation,
  profileId: spawned.info.profileId,
};
const resumed = await runtime.resume({
  continuation: saved.continuation,
  profile: saved.profileId,
});

A profile that cannot be resolved for the selected provider produces AGENT_PROFILE_NOT_FOUND on spawn/resume. A host handling native invocations can seed the terminal environment with profileBindingEnvironment(); supported adapters preserve and attribute the binding through invocation normalization.

Value Meaning
AgentProfile.dataRoot The profile’s allocated native binding root.
profileBindingEnvironment() Provider-owned environment overrides that make a process use that profile.
profileObservationRoot() The directory to which an external indexer applies that provider’s native history layout. Pi and OpenCode derive this at a different level from dataRoot.
AgentSessionInfo.profileId Account attribution for the live run. The host can persist it alongside the continuation.
Indexer handoff. The runtime supplies a layout root; it does not register that root with Rosetta or start an indexer. The application owns that integration. See aggregation ownership.

Account usage & push updates

Account quotas are shared by sessions using the same account. Per-run token totals and burn rate remain on the Agent monitor.

AgentRuntime · excerpt

interface AgentRuntime {
  accountUsageProviders(): readonly AccountUsageProvider[];

  onAccountUsage(listener: (provider: AccountUsageProvider, result: AccountUsageFetchResult) => void): () => void;

Method Contract
accountUsageProviders() Returns provider identity and recommended polling cadence. It does not start a polling loop.
accountUsage() Fetches the native-default account when no profile ID is supplied, or resolves the named profile. Concurrent calls coalesce per provider/profile target. onAccountUsage() Receives push updates from providers that implement AccountUsageService.subscribe(). Separate from agent.on(); not every provider pushes. It is not an automatic broadcast of every explicit fetch.

Rule Consumer behavior
Metric order and IDs Preserve adapter-ranked order and render the supplied label. Metric IDs are opaque; duplicate IDs are rejected by the schema.
Percentages and credits usedPercent is nonnegative and can exceed 100. Credits, when present, contain at least one value. Preserve provider-formatted balance strings and optional fields.
Failures and attribution Unsupported provider/profile requests return typed failures; native fetch errors normalize to unavailable. Failures identify the provider, while the caller retains its requested profile association.
Polling and push Use pollIntervalMs and optional pushUpdatePollIntervalMs as provider recommendations. The application owns scheduling, caching and display policy. Honor retryAt when provided.
Lifetime Unsubscribe when the consumer is released. Async management operations generally reject after runtime disposal; data failures do not make every API non-throwing.

Account quota

runtime.accountUsage(): normalized subscription/API/workspace limits and credits.

Live burn rate

agent.monitor.usage: the run’s normalized token accounting, including supported child usage. See the monitor reference.

Restored usage bars

Godview persists its UI ledger by provider/native session. This is an app cache of observed usage, not a transcript-based recalculation.

The monitor state contract owns live usage and subagent aggregation. Search results and quota percentages do not become token samples.

Provider service contracts

Adapters implement native behavior behind these Core contracts. Runtime composition attaches the services to AgentProvider; applications consume the normalized runtime methods.

interface ProfileService {
  readonly provider: ProfileProvider;
  /**
   * Variables that bind a child process to the profile root. Names must be a
   * subset of the provider's launch allow-list; empty for the native default.
   */
  bindingEnvironment(profile: AgentProfile): Record<string, string>;
  /**
   * The directory whose provider-native layout holds this profile's durable
   * history — transcripts and session stores — and therefore the directory an
   * external history indexer applies the provider's layout to.
   *
   * A native-default profile answers with the provider's own layout root; a
   * managed profile answers with a path derived from `dataRoot` by the same
   * binding rule `bindingEnvironment` applies. It is not always `dataRoot`:
   * Pi binds one level inside it and OpenCode's history sits under the

   * provider-specific, so it is an adapter-owned rule rather than a schema
   * field a host could fill in.

  initializeRoot?(profile: AgentProfile): Promise<void>;

   * The native interactive login for a host terminal. The host merges
   * bindingEnvironment(profile) over spec.env and over its clean environment.

  verify(profile: AgentProfile): Promise<ProfileIdentity | ProfileFailure>;
}
interface AccountUsageService {
  readonly provider: AccountUsageProvider;

  subscribe?(listener: (result: AccountUsageFetchResult) => void): () => void;
}

The runtime validates declared descriptors and normalized results against Core schemas. Adapters determine native commands and layout; the runtime executes declared release detectors and update recipes. Terminal interaction goes through the application-owned AgentHost.

Profile defaults are app policy and do not change existing processes.

Godview usage persistence

The renderer keeps held totals and step snapshots so a resumed conversation can restore its usage bars. Main stores this ledger under the application cache directory.

PuppeteerBridge · excerpt

interface PuppeteerBridge {
  loadUsageHistory(key: UsageHistoryKey): Promise<UsageLedgerRecord | null>;
  saveUsageHistory(records: UsageLedgerRecord[]): Promise<void>;
}
Method Contract
loadUsageHistory() Returns the saved ledger for a provider/native-session pair, or null.
saveUsageHistory() Merges supplied ledger records by conversation key, then prunes and writes the cache. It does not ingest transcript content. 
interface UsageSeriesRecord {
  held?: number;
  snapshots: number[];
}

interface UsageLedgerRecord {
  providerId: string;
  nativeSessionId: string;
  /** ISO time of the save. */
  savedAt: string;
  /** The last step boundary snapshotted, in steps since the epoch. */
  boundary: number;
  total: UsageSeriesRecord;
  output?: UsageSeriesRecord;
  input?: UsageSeriesRecord;
}

interface UsageHistoryKey {
  providerId: string;
  nativeSessionId: string;
}

On save, the store prunes records older than 30 days and retains at most 1,000 records. Its reader rejects files larger than 4 MiB, and each series is bounded to 64 snapshots. These are current Godview cache limits, not runtime token accounting semantics.
