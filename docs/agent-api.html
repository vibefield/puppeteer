Architecture

Provider details end at the adapter boundary. Every downstream service consumes the same normalized, ordered envelope, and each runtime run has exactly one owning Agent instance.

Quick start

Create through the runtime; do not construct Agent directly. Spawn failures are returned as data, so narrow the result before subscribing. 

import { createBuiltinAgentRuntime } from '@vibecook/puppeteer-runtime';

const runtime = createBuiltinAgentRuntime({ host, defaultCwd: process.cwd() });

const result = await runtime.spawn({
  agent: 'claude',
  workspace: { mode: 'worktree', path: process.cwd() },
  agentOptions: { model: 'sonnet', permissionMode: 'plan' },
});

if ('error' in result) throw new Error(result.error.message);
const agent = result;

const offState = agent.on('state:*', (envelope) => {
  console.log(envelope.type, agent.state.lifecycle);
});

const offContext = agent.on('context-window:updated', ({ event }) => {
  console.log(`${event.usedTokens}/${event.capacityTokens}`);
});

const offAll = agent.on('*', ({ service, type, sequence }) => {
  console.log(sequence, service, type);
});

const receipt = await agent.submitPrompt({ text: 'Review this repository' });

offState();
offContext();
offAll();
Subscription timing. Adapter bootstrap events are buffered until the runtime attaches the owning Agent. Application listeners added after spawn() observe subsequent live events; use agent.state and agent.conversation for the already-projected current snapshot.

Subscriptions and typed selectors

Selectors narrow the listener envelope at compile time. All forms receive the same immutable envelope; only their routing breadth differs.

exact

'context-window:updated'

AgentEventEnvelope<ContextWindowUpdatedEvent>

One public route. Best when a consumer owns one concrete behavior.

service

'state:*'

AgentEnvelopeForService<'state'>

Every route owned by the service. The nested event remains a discriminated union.

catch-all

'*'

AgentEventEnvelope<AgentEvent>

Every normalized envelope for logging, diagnostics, replay, or generic instrumentation.

type AgentEventSelector =
  | '*'
  | `${AgentEventService}:*`
  | AgentServiceEventType;

const unsubscribe = agent.on('state:tool-completed', ({ event }) => {
  // event is ToolCompletedEvent here
  console.log(event.toolCallId, event.durationMs);
});

unsubscribe();
Delivery contract. Publication is synchronous. The Agent updates its state and conversation projections before invoking listeners. A listener exception is reported through the runtime error hook and does not stop other listeners or adapter ingestion. Do not depend on relative ordering between listeners registered on different selector scopes.

The event envelope

Subscribe using the namespaced envelope type. Inspect the nested event.type only when discriminating normalized payloads inside a wildcard listener. Raw provider evidence, when retained, stays in nativeEvent. 

interface AgentEventEnvelope<T extends AgentEvent = AgentEvent> {
  type: AgentServiceEventType<T>; // public route, e.g. "state:turn-started"
  service: AgentEventServiceOf<T>;
  eventId?: string;
  sourceEventRef?: {
    namespace: string;
    eventId: string;
    revisionKey?: string;
    sourceGeneration?: number;
    cursorStart?: number;
    cursorEnd?: number;
  };
  sequence: number;               // monotonic delivery order for this Agent
  sessionId: string;
  nativeSessionId?: string;
  promptId?: string;              // user-turn correlation
  turnId?: string;                // assistant response-cycle correlation
  agentId?: string;               // provider-native actor; absent means root
  agentType?: string;
  providerVersion?: string;
  timestamp: string;              // ISO 8601 wall-clock time
  monotonicTime: number;
  source: AgentEventSource;
  confidence: AgentEventConfidence;
  replay?: boolean;               // durable history, not a new live event
  event: T;                       // normalized provider-neutral payload
  nativeEvent?: unknown;          // retained raw provider evidence
}
route type + service drive fan-out identity ids correlate run, turn, actor, and source evidence source + confidence explain trust escape hatch nativeEvent retains raw evidence

Monitor batch update algebra

Monitor batches are the one event whose nested value system is correction-aware. Every metric-family update is an upsert, keyed retraction, or complete/partial replacement.

  | 'status' | 'usage' | 'context' | 'model' | 'effort' | 'mode'
  | 'planning' | 'delegation' | 'workflow' | 'compaction' | 'environment';

type MonitorFamilyUpdate =
  | {
      family: MonitorMetricFamily;
      operation: 'upsert';
      key: string;
      value: MonitorFamilyValue;
    }
  | {
      family: MonitorMetricFamily;
      operation: 'retract';
      key: string;

  | {
      family: MonitorMetricFamily;
      operation: 'replace';
      values: Array<{ key: string; value: MonitorFamilyValue }>;
      coverage: 'complete' | 'partial' | 'unavailable';

Operational semantics

The invariants consumers can safely design around.

One owner

Each managed spawn, adoption, or restore has one runtime Agent and one adapter subscription.

Normalized boundary

Provider-native names and shapes do not escape as public routes. Unknown evidence is retained explicitly.

Stable ordering

The runtime restamps monotonically increasing sequence numbers before projection and fan-out.

Idempotent state

The reducer ignores non-increasing sequence numbers and records bounded diagnostics for invalid transitions.

Separate identities

Runtime run, terminal session, native session, prompt, turn, and actor correlations are not collapsed.

Separate facts

Process exit, semantic session exit, turn completion, context pressure, token burn, and account quota are distinct.

Safe listener faults

One observer cannot break ingestion or prevent other observers from receiving the same envelope.

Explicit uncertainty

Evidence carries source/confidence, replay is marked, and prompt submission may return uncertain.
