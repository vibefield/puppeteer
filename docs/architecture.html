Architecture & Repository Guide

Puppeteer hosts coding agents' native terminal experiences while adding evidence-backed observation, provider-neutral control, ordered events, workspace ownership, and portable monitoring. This document explains where every responsibility lives and which contracts cross each boundary.

Fundamentals

The architecture begins with one product choice: the coding agent owns its native terminal interface. Puppeteer owns the process environment around it and learns semantic state from structured native evidence—not from pixels or terminal text.

Two foundations, not one stack. Surface records provider-native reality. Core defines Puppeteer's provider-neutral contract. They deliberately do not depend on each other. Adapters bridge the two concepts through reviewed implementation and conformance, not through a production import from Surface.
native truth

Evidence before interpretation

Artifacts, hooks, protocols, logs, captures, and exact source establish what a provider really does. Capture representation and schema fidelity are machine-readable; missing evidence remains an explicit limitation.

portable contract

Normalize once at the boundary

Provider names and payloads end inside an adapter. Core schemas define the stable event and service vocabulary consumed by Runtime and products.

ownership

One run, one Agent

Each accepted provider process or thread has one runtime run, one adapter binding, one private event bus, and one owning Agent object.

separation

Facts are not commands

Events report observations. Prompt submission travels through a named service port. Event payloads never carry callbacks or command functions.

state

Projection is downstream

Adapters emit facts, not application state. Runtime projects session state and monitor snapshots from the same validated, ordered envelopes.

presentation

Views receive data and actions

Monitor views do not know about providers, PTYs, IPC, or adapter internals. Products may enrich the portable projection with terminal and layout concerns.

uncertainty

Evidence quality stays visible

Source, confidence, replay state, freshness, completeness, and observation capability are modeled rather than flattened into false certainty.

identity

Correlations stay distinct

Runtime run, terminal session, native session, prompt, turn, actor, workspace, and source-event identities are related but never collapsed into one ambiguous id.

System map

Solid arrows are production dependencies or runtime flow. The dashed Surface-to-adapter edge is a development and conformance relationship: production adapter code targets Core and carries a digest-locked mapping instead of importing provider evidence.

Dependency direction is policy. The exact allowed production edges live in scripts/check-package-layout.mjs. A cycle, unregistered package, concrete adapter import from Runtime, or upward presentation dependency fails the repository gate.

The layer model

Each layer has one reason to change and a narrow output boundary. The stack is intentionally asymmetric: native fidelity moves upward through normalization, while commands move downward through explicit capabilities.

Core: the provider-neutral language

@vibecook/puppeteer-core contains contracts and pure logic only. It does not open files, spawn processes, contact providers, or know which official adapters exist.

events/<category>.ts

One module owns each event category's payload schemas and inferred TypeScript types. Routes always follow category:event-name.

adapter/

Defines AgentAdapterBinding, unstamped AdapterEventCandidate, and the buffered candidate source.

services/

Provider-neutral command and query ports: prompt submission, event source, and account usage.

monitor/ + state.ts

Pure reducers and projection contracts for session state, three-state monitoring, freshness, ordering, bounds, notifications, and subagent aggregation.

The public categories are session, turn, reasoning, tool, interaction, delegation, compaction, context-window, conversation, usage, environment, model, effort, mode, workspace, process, notification, monitor, and adapter. Their exact routes and payloads are cataloged in Agent API.

Schema decision. Zod validates data where untrusted runtime values cross into Core. TypeScript supplies compile-time unions, callback narrowing, and internal composition. Provider wire decoding remains tolerant until the normalized boundary.

layer0

Ground truth: what the provider actually does

@vibecook/puppeteer-surface owns captured native reality. Every real vendor has one stable runtime authority at packages/surface/vendors/<vendor>/groundtruth.json. Its embedded manifest selects the active native version; Git history records how that one file evolves.

Authoring inputs

Versioned manifests, evidence, channels, behavior, native event schemas, captures, probes, census tools, exact-source references, and findings.

Fidelity contract

Every capture set declares type-preserving, semantic-projection, or legacy-projection fidelity. ASM v3 separately records exact, semantic, structural, sampled, or unknown schema fidelity plus evidence-bound nested refinements.

Complete discovery

upstream.json declares the vendor inventory. Workflow and audit gates start there, so a missing model, generator, audit, sanitizer, privacy gate, or canonical output cannot disappear from CI.

Canonical output

One deterministic groundtruth.json plus a derived local groundtruth.html explorer. Only the JSON is published.

Consumer relationship

Imposter loads the canonical document directly. Adapter code is reviewed against it and records the digest and native-name partition in groundtruth-map.json.

Not its job

Surface does not define normalized events, product state, UI behavior, or a promise that every native method becomes public.

layer1

Imposter: native-compatible behavior without the vendor

@vibecook/puppeteer-imposter is one executable that can stand in for every modeled coding agent. It speaks the vendor's actual machine surfaces—hooks, JSONL, JSON-RPC, HTTP/SSE, status lines, sockets, and leader channels—so adapters are tested against native-shaped behavior.

personas/<vendor>/

Stable Surface reference, operation bindings, native scenarios, runflows, behavior fixtures, and optional served request results.

session/channels/

Vendor-native carriers. Each channel implements framing and delivery without introducing Core event semantics.

control/ + scenario driver

A development protocol for triggering operations, pausing or stepping scenarios, inspecting native emissions, and injecting faults.

bin/ai.mjs + tui/

Unified executable and lightweight presentation. The fake screen is diagnostic; adapter semantics still come only from native-shaped machine channels.

Boundary rule. Imposter depends only on Surface. It does not import Core, adapters, Runtime, Monitor, or React, and it does not pre-normalize the behavior an adapter is supposed to prove.

layer2

Adapters: translate native reality into Core

Each packages/adapter-* package owns one provider or protocol. It decodes upstream records tolerantly, observes live and durable native sources, emits category-focused Core candidates, and implements explicit capability services. 

packages/adapter-<vendor>/
  groundtruth-map.json          # digest-locked reviewed native mapping
  src/
    normalization/
      <category>.ts             # one Core event category per file
      monitor.ts                # correction-aware monitor evidence
      pipeline.ts               # composes normalizers; contains no category logic
    services/
      <capability>.ts           # one explicit control/query capability
    observation/                # native live and durable evidence sources
    transport/                  # protocol framing, clients, connections
    launch/                     # authoritative executable preparation
    test-support/               # unpublished fakes only
    driver.ts                   # composition into AgentAdapterBinding
    index.ts                    # canonical public exports

Observation rail

events.onCandidate(…) is the only adapter-to-runtime normalized rail. Candidates have a route and payload, but no runtime epoch or delivery sequence.

Capability rail

services.prompt is required; Unsupported capabilities are absent rather than simulated with events.

Host rail

Adapters request terminal spawn and atomic automation through AgentHost. The application retains PTY/process ownership.

Unknown evidence

Meaningful but unmapped native records become adapter:native-event; they are not silently discarded or guessed into a known category.

File-operation evidence

workspace:file-operation correlates a mutating tool and preserves its proposed, in-progress, applied, or failed phase. Native watchers instead emit workspace:file-changed without an invented tool id. Applied means the native operation reported success, not that Puppeteer independently read the file back.

Exactness without fabrication

Paths, kinds, moves, raw diffs, bounded diff previews, writes, and replacements are carried only when Layer 0 proves that native field. Each detail records whether it came from tool input, tool result, or the native file-operation carrier, and complementary details may coexist. Missing detail stays absent; presentation previews never masquerade as exact patches, and a proposed edit is never reported as an applied filesystem mutation.

layer3

Runtime ingress and event bus: one ordered truth rail

Layer 3 lives inside @vibecook/puppeteer-runtime. It accepts normalized but unstamped adapter candidates, creates public envelopes, updates projections, and publishes on a private bus owned by one Agent controller.

Validate candidate metadata

Reject malformed correlation, source identity, timestamps, confidence, or actor attribution.

Resolve route and validate payload

The exact category:event-name selects its Core Zod schema.

Correlate identity and deduplicate

Bind runtime/native ids and stable source references without confusing replay with delivery.

Assign monotonically increasing delivery order

Runtime—not adapters—owns the per-run sequence visible to every downstream consumer.

Project and publish

State and monitor consume the same envelope before typed Agent fan-out.

AdapterEventCandidate
  → metadata schema
  → route-specific event schema
  → identity + source deduplication
  → RuntimeAgentEventEnvelope { runtimeRunId, runtimeEpoch, sequence }
  → state · monitor · private AgentEventBus
Category is routing, not service ownership. A projector may consume several event categories. Category modules define fact schemas; Runtime services define the state they project.

layer4

Agent: the object applications program against

Runtime constructs exactly one Agent per accepted run. Applications never construct it directly and never receive the internal controller. The object combines stable identity, defensive snapshots, typed subscriptions, and explicit control.

identity

info · runtimeRunId · terminalSessionId

Run, native session, terminal routing, external reference, and workspace identity.

projection

state

A defensive provider-neutral state snapshot derived from the ordered event rail.

operations

lifecycle · alive · status · monitor

Detailed lifecycle and process liveness remain separate from operational idle | working | blocked.

events

on(exact | category:* | *)

Typed subscriptions to immutable envelopes. One listener fault cannot interrupt ingestion.

Returns a confirmed, rejected, or uncertain receipt from the adapter prompt service.

monitor

Race-free monitoring of state and transition notifications.

Detailed API companion. The complete class declarations, Runtime surface, envelope fields, selector typing, projections, and all normalized routes live in Agent API & Event Catalog.

layer5

Presentation: portable monitor state before product UI

Layer 5 separates monitoring delivery from any renderer. Core defines the serializable state; @vibecook/puppeteer-monitor stores it; @vibecook/puppeteer-react binds it to React; products decide how to display and interact with it.

monitor

A framework- and transport-neutral external store with epoch/revision ordering, removal tombstones, bounded notifications, deduplication, and referentially stable snapshots.

react

useSyncExternalStore hooks for all runs, one run, and notifications, plus the generic AgentMonitorViewDefinition plugin contract.

apps/godview

Product composition: Electron, terminal panes, recovery, IPC, workspace slots, account usage, and swarm-specific projections and actions.

Product boundary

A view receives projected items, actions, and parameters. It does not open native provider files, import adapters, or infer semantics from terminal content.

Folder and file conventions

Directory names communicate ownership. A contributor should be able to answer “what boundary am I implementing?” from the path before reading the file.

event schema

core/src/events/<category>.ts

Defines one category's event payloads, Zod schemas, route literals, and TypeScript unions.

  • Every event extends the unified event contract.
  • Route is always category:event-name.
  • No provider-native names or callbacks.
service contract

core/src/services/<capability>.ts

Defines a command or query needed by an upper layer independently of any provider.

  • Methods return typed results.
  • Optional capability means optional port.
  • Commands are never encoded as events.
normalizer

adapter-*/normalization/<category>.ts

Maps one family of native facts into one Core category and nothing else.

  • Wire decoding happens before strict Core validation.
  • Cross-category composition belongs in the pipeline.
  • No stateful product projector lives here.
service adapter

adapter-*/services/<capability>.ts

Adapts a provider control or query surface to one upper-level Core service.

  • File name matches the capability it satisfies.
  • Provider auth and protocol quirks stay private.
  • Receipts admit uncertainty.
projector

runtime/src/services/<projection>-service.ts

Consumes ordered envelopes and owns one Agent-facing projection or capability facade.

  • May consume multiple event categories.
  • Returns defensive snapshots.
  • Does not decode native provider records.
view

product or react view module

Transforms monitor state plus explicit actions/parameters into presentation.

  • No adapter or provider-file imports.
  • No terminal-text semantic inference.
  • Product-only facets stay outside portable Core state.

Repository-wide code conventions

ESM imports

Relative TypeScript imports end in .js. Imposter alone uses .ts so its executable can run source through Node type stripping; emit rewrites them for distribution.

Public exports

Package index.ts files expose canonical modules directly. Do not add duplicate compatibility barrels, top-level normalizer shims, or rollout-only bridges.

Source and publish

In-repository exports target src; publishConfig remaps the same export keys to dist. Package audits inspect the resulting tarballs.

Tests

Unit tests live beside the module they prove. Cross-provider behavior uses the shared testing conformance suites; live native probes are opt-in.

Errors

Expected operational failures return discriminated result objects. Throw for programmer mistakes, malformed trust-boundary input, or broken invariants.

Comments

Explain ownership, protocol quirks, security boundaries, and rationale—not a restatement of syntax.

Top-level consumer-facing contracts and APIs

Most products need only the turn-key Runtime and the per-run Agent. Lower-level packages exist for custom hosts, provider authors, monitor transports, development tools, and tests.

1. Product application: built-in Runtime → Agent

@vibecook/puppeteer-builtin-providers is the normal composition root. It supplies every official provider behind a discriminator-narrowed Runtime facade. 

import { createBuiltinAgentRuntime } from '@vibecook/puppeteer-builtin-providers';

const runtime = createBuiltinAgentRuntime({
  host,                         // application-owned AgentHost
  defaultCwd: projectRoot,
});

const result = await runtime.spawn({
  agent: 'claude',
  cwd: projectRoot,
  workspace: { mode: 'worktree' },
  agentOptions: { model: 'sonnet' },
});

if ('error' in result) {
  renderSpawnFailure(result);
} else {
  const agent = result;
  const unsubscribe = agent.on('tool:*', (envelope) => {
    consumeToolEvent(envelope.event);
  });

  const receipt = await agent.submitPrompt({ text: 'Review this change.' });
  const continuation = agent.info.continuation;
  const resumed = await runtime.resume({ continuation });
  unsubscribe();
}

await runtime.dispose();

Provider management and application aggregation

Providers and accounts

Runtime owns installation inventory, release execution, profile registry and quota validation. Adapters supply native commands, root bindings and evidence interpretation. Hosts inject persistence and scheduling. See Agent Management API.

History and live discovery

Godview’s Find sheet calls its history bridge and main-process client. An external Rosetta-compatible daemon owns transcript indexing; native session IDs join results to live runs. Search feeds navigation. See Agent Aggregation API.

2. Custom composition: Runtime + AgentProvider + AgentHost

Use @vibecook/puppeteer-runtime directly when an application supplies a custom provider set. Runtime remains provider-agnostic; provider-specific assembly happens outside it. 

import { createAgentRuntime } from '@vibecook/puppeteer-runtime';

const runtime = createAgentRuntime({
  host,
  defaultCwd,
  providers: [customProvider],
  recorder,
  creationRegistry,
});

interface AgentProvider {
  readonly descriptor: AgentProviderDescriptor; // strict Zod data contract
  readonly executionMode?: 'native-tui' | 'structured' | 'acp';
  createSession(options: AgentProviderSessionOptions): Promise<AgentAdapterBinding>;
  prepareSession?(options: AgentProviderSessionOptions): Promise<PreparedProviderSession>;
  readonly launch?: AgentProviderLaunchService;
  readonly accountUsage?: AccountUsageService;
  readonly distribution?: DistributionService;
  readonly profiles?: ProfileService;
  prewarm?(options: { profile?: AgentProfile; signal: AbortSignal }): Promise<void>;
  attachSession?(options: AttachProviderSessionOptions): Promise<AgentAdapterBinding>;
  dispose?(): void | Promise<void>;
}

interface AgentProviderDescriptor {
  id: string;                 // stable and opaque outside the adapter/runtime
  label: string;              // adapter-authored consumer display label
}

interface AgentProviderLaunchService {
  readonly provider: AgentLaunchProvider; // strict Zod data contract
  normalizeInvocation?(input: AgentNativeInvocation): AgentNativeInvocationResolution;
  readonly continuation?: {
    // adapter state is also strict, versioned Zod data
    capture(options: AgentProviderSessionOptions): string | undefined;
    restore(state: string | undefined, options: { cwd: string }): unknown;
  };
}

Provider management is defined in the DistributionService, ProfileService and AccountUsageService contracts. The management reference owns their DTOs, native evidence rules, profile-scoped fetch and account snapshot shapes.

Host contract. AgentHost is deliberately tiny: spawnTerminal(spec) and automateTerminal(id, operation). Ghosttea or another application terminal service owns PTYs, focus, resize, accepted human input, and process lifecycle.

3. Adapter author: AgentAdapterBinding

This is the only provider-specific seam consumed by Runtime. Application code should consume Agent, not this low-level handle. 

interface AgentAdapterBinding {
  readonly sessionId: string;          // provider-native identity
  readonly runtimeSessionId: string;   // host terminal routing identity
  observationLevel(): ObservationLevel;
  readonly events: {
    onCandidate(listener: (candidate: AdapterEventCandidate) => void): () => void;
  };
  readonly services: {
    readonly prompt: AgentPromptService;
  };
  dispose(): Promise<void>;
}

AdapterEventCandidate

Canonical route, normalized payload, native/session/actor correlations, timestamp, source, confidence, replay flag, and optional raw native evidence. Runtime identity and sequence are absent.

AgentEventEnvelope

Runtime-stamped public fact with type, category, sequence, source identity, correlations, evidence metadata, normalized event, and optional native record.

AgentPromptService

submit({ text, mode?, confirmationTimeoutMs? }) returns confirmed | rejected | uncertain.

Control, event, and monitoring flow

Observation and control travel on different rails. Their only intentional convergence is native confirmation: a command may cause provider behavior that is later observed as ordinary evidence.

Observation flow

native hook / protocol / log / workspace / process evidence
  → adapter observation source
  → tolerant provider decoder
  → normalization/<category>.ts
  → AdapterEventCandidate
  → Runtime validation + identity + dedup + sequence
  → state / monitor projectors
  → private Agent event bus
  → agent.on(…) listeners

Control flow

application
  → agent.submitPrompt({ text })
  → runtime prompt facade
  → adapter services/prompt.ts
  → native structured protocol OR AgentHost.automateTerminal(…)
  → provider process
  → confirmed / rejected / uncertain receipt

provider response evidence returns independently through the observation flow

Monitor delivery flow

Do not close the loop through terminal text. The terminal exists for the human and the native agent. It may carry control bytes through the host, but it is never a semantic observation parser.

Non-negotiable invariants

These constraints keep provider fidelity, portable contracts, runtime ownership, and product presentation independently evolvable.

No terminal semantics

Never infer agent state from terminal text, screen scraping, focus, or visual presentation.

No shadow agent

One runtime run owns at most one primary interactive agent process; no print/exec mirror process.

Stable event routes

Every public event route follows category:event-name and validates in Core.

Runtime owns envelopes

Adapters never assign runtime epochs, public categories, or delivery sequence numbers.

Services own commands

Callbacks and operations never hide inside event payloads; optional capability is an optional port.

One canonical ground truth

Each agent has one vendor-root JSON authority; versioned model trees are inputs only.

Declared truth inventory

Every upstream.json vendor participates in workflow, audit, and canonical checks.

Projections cannot masquerade as schemas

Capture and schema fidelity are explicit; discarded native shape remains a limitation, never an inferred contract.

No concrete adapter in Runtime

Runtime consumes AgentProvider; official provider imports stop in composition.

Imposter remains native

It depends only on Surface and never smuggles normalized Core semantics into adapter tests.

Lifecycle is not status

Detailed session/process lifecycle remains orthogonal to idle | working | blocked.

Unknowns stay visible

Unknown meaningful native records, degraded rails, gaps, corrections, and uncertainty are explicit.

Credentials stay ephemeral

Launch environments may carry bearer tokens; logs, artifacts, and snapshots must not persist them.

Package graph stays acyclic

Every internal production edge is explicit, allowlisted, and continuously checked.

Where a change belongs

Start with the responsibility, not the most convenient existing file. If a change crosses several rows, keep each piece at its owning layer and compose them through the documented contracts.
