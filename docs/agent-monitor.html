End-to-end system map

One runtime-owned monitor service reduces three evidence planes for each runtime run. Consumers receive full replacements, never patches. Godview’s global callbacks discover runs; the actual main-process stream comes from a race-free per-run handle and crosses the renderer boundary through a revision-aware relay.

Canonical seam. Provider-native facts stop at adapter normalization. Product views receive MonitorAgent[], actions, and parameters; they do not import Runtime, adapters, IPC, terminal internals, or provider files.

The monitor is a sequence of narrow contracts, not a React feature reaching backward into an agent. Each package owns one concern and the production dependency direction is enforced by repository checks.

Runtime projection

AgentMonitorService is both an Agent projection service and the shared source for every per-run handle. It validates semantic batches, translates ordinary normalized events, accepts workspace observations, and publishes only when the public projection changes.

semantic plane

Adapter-issued monitor:batch data with producer epoch, optional sequence, capabilities, coverage, evidence, and bootstrap/live/correction/resync phase.

runtime plane

Ordinary Agent events translated to monitor updates, plus exact runtime lifecycle and prompt receipts. Only host evidence can prove process death.

workspace plane

Runtime-owned cwd, Git, worktree, allocation, baseline, finalization, and interference evidence. Private provenance is not copied wholesale into renderer state.

Publication policy

Ordinary change

Coalesced for 100 ms by default, so bursts produce fewer full-state publications.

Urgent change

Alive transitions, blocker changes, native-session identity, and readiness barriers flush immediately.

Scheduled truth

Activity leases, burn-rate windows, and the 30-second freshness boundary trigger clock-owned projections.

No public change

The projector returns the previous object, preserving reference identity and revision.

Transition notice

Derived from unbounded before/after projections; bootstrap, correction, resync, and replacement stay silent.

Terminal failure

The service can freeze a bounded final public snapshot after releasing provider and scheduler resources.

Three orthogonal answers. agent.lifecycle describes detailed session phases, agent.alive is host-owned process liveness, and agent.status is the product-facing idle/working/blocked projection.

Public monitor API

Application code normally starts from the Agent returned by spawn(). Host and IPC integrations can use the Runtime-wide lookup and discovery methods. The handle is the race-free, per-consumer streaming surface. 

const result = await runtime.spawn({
  agent: 'claude',
  workspace: { mode: 'worktree', path: process.cwd() },
});
if ('error' in result) throw new Error(result.error.message);

const agent = result.agent;
console.log(agent.alive, agent.status, agent.monitor.revision);

const handle = agent.observeMonitor();
await handle.ready;

void (async () => {
  for await (const state of handle.states) renderLatest(state);
})();

void (async () => {
  for await (const notice of handle.notifications) enqueueNotice(notice);
})();

// Closing this consumer never closes the provider session.
await handle.close();

State queue

Conflated: a slow consumer receives the latest full replacement, not every intermediate revision.

Notice queue

FIFO and bounded. Overflow rejects the iterator with MonitorNotificationGapError; resubscribe for current state.

Initial race

The source subscribes before reading current(); equal or older snapshots are rejected.

Transport-neutral store and React bindings

@vibecook/puppeteer-monitor accepts any transport that can list current states and publish state, notification, and removal messages. @vibecook/puppeteer-react is deliberately thin: four hooks plus generic view props and a view definition. 

const store = createAgentMonitorStore({ notificationCapacity: 4 });
const connection = connectAgentMonitorStore(store, source);
await connection.ready;

function MonitorPanel({ runtimeRunId }: { runtimeRunId: string }) {
  const state = useAgentMonitor(store, runtimeRunId);
  const notifications = useAgentMonitorNotifications(store);
  // ...
}

connection.close();

No blessed UI component. The React package does not prescribe a card, table, swarm, or status color. It standardizes subscription behavior and the data/actions/parameters seam so products can own their interface without breaking runtime boundaries.

Godview interface design

Godview is both a monitor and a terminal workspace. Its shell owns chrome and terminal actions; the active registered view receives only a product projection. The inspector is shell-owned because it follows the currently mounted agent rather than defining another topology view.

Main → preload → renderer transport

The main process keeps reconnect state in MonitorIpcRelay, maps stable runtime runs to current terminal sessions, and broadcasts through a narrow preload bridge. The renderer subscribes before concurrently listing sessions and monitor snapshots, so live publications win over stale bootstrap results.

Bridge surface Direction Payload / behavior

Sorted reconnect snapshot of relay-held full states.

Run id, nullable terminal id, and full state.

Ephemeral transition notice; main intentionally does not retain notices.

Terminal is a facet boundary. Unclaimed terminals remain visible without inventing an Agent monitor. Agent-backed rows appear only when a canonical monitor state exists. Stable handoff identity preserves view-local placement when an ended agent PTY becomes a live shell.

Registered views

swarm

Matter.js spatial field. Bubbles are draggable and selectable; a 520 ms empty-stage long press creates a terminal at that point. Agent idle uses the working-size body, working becomes ignited, and blocked remains blocked.

list

Non-spatial proof of the same contract. Agent-backed rows precede terminals, then sort blocked → working → idle and by creation time. It ignores spawn hints and creates terminals without position.

inspector

Shell-owned detail for the active agent: metrics, blockers and structured questions, tasks, actors, teams, workflows, artifact previews, environment, readiness, and bounded omissions.

view registry

A view is one directory and one registry entry. Its component receives agents, actions, and normalized per-view parameters—never runtime or workspace objects.

Status and freshness stay separate

idle

No projected blocker and no active projected activity. The process may be alive or ended.

working

No blocker and an active projected activity, selected by deterministic priority.

blocked

At least one pending permission/question or active failure. Failure outranks question, then permission.

freshness

Support, availability, and fresh/stale/unknown recency are metadata; staleness never creates a fourth status.

Transition notifications

Notifications are attention hints, not a second source of truth. Current types cover blocker entry, plan and task transitions, subagents, teams, workflows, compaction, cwd/worktrees, and session end.

Ordering, removal, and renderer recovery

The same strict rule is shared by Core, the main relay, and the renderer store: higher runtime epoch wins; within one epoch, only a higher revision wins. Removal seals an epoch, so late publications cannot resurrect a dead run. A durable identity can return only at a provably newer epoch. 

function isNewerMonitorRevision(candidate, current) {
  return candidate.runtimeEpoch > current.runtimeEpoch ||
    (candidate.runtimeEpoch === current.runtimeEpoch &&
      candidate.revision > current.revision);
}

function isMonitorStateAfterRemoval(state, sealedEpoch) {
  return sealedEpoch !== null && state.runtimeEpoch > sealedEpoch;
}

Runtime handle

Subscribes before reading current state. State is conflated; notification overflow is explicit.

Main relay

Retains current reconnect state, up to 2,048 removal tombstones, and a 1,024-id notification dedupe window.

Renderer store

Deep-freezes accepted JSON trees, seals removals, and exposes stable snapshots to React.

Godview bootstrap

Installs live listeners first, then lists sessions and monitors in parallel and merges without overwriting newer data.

Trust, safety, and privacy boundaries

Monitor state is intended for renderers, but artifact content and renderer-issued actions cross a stronger boundary. Godview validates the sender, treats identities as opaque labels, imposes hard byte limits, and removes provider-authored failure text from unsuccessful reads before returning it to the renderer.

No terminal semantics

Neither monitor status nor activity is inferred from terminal text. Native hooks/protocols/logs and explicit host/workspace evidence supply meaning.

Renderer isolation

Electron main owns Runtime. Preload exposes a narrow contextBridge; requests are accepted only from a registered Godview tab.

Opaque identifiers

Run, blocker, and artifact ids are trimmed labels up to 512 characters—not paths, file URLs, drive paths, or NUL-bearing values.

Bounded artifacts

Runtime default is 256 KiB, hard maximum is 1 MiB, and the inspector asks for 64 KiB. Every attempted read is auditable.

Narrow acknowledgment

IPC acknowledgment works only for a retained, dead failure blocker. Permission and question blockers remain owned by the native agent interaction.

Bounded public state

Collections are deterministically capped and omissions disclosed. Large evidence ledgers and workspace provenance remain private to the accumulator.

Workspace detail boundary. The public environment may include cwd, Git state, and worktree paths. Touched file identities, file contents, fingerprints, and detailed workspace provenance do not enter the monitor snapshot by default; detailed normalized Agent events remain a separate authorized rail.

Artifact action path

React inspector
  → PuppeteerBridge.readAgentMonitorArtifact({ runId, artifactId, maxBytes })
  → sender + opaque-id + safe-integer + 1 MiB validation
  → relay confirms the run is currently known
  → Runtime resolves the projected ArtifactRef
  → adapter services.artifacts.read(opaqueId, { maxBytes })
  → returned bytes checked again
  → audit record
