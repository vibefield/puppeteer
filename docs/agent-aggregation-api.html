Architecture & ownership

Aggregation combines the live agents known to the application with indexed facts and matching transcript text. The implemented search service lives in Godview’s product layer.

Live facts

The local Find model matches titles, summaries, project, branch, model, provider, account, status and detail.

Indexed words

The main-process client asks the daemon for matching prompts and replies, scoped to native sessions when supported.

One row per agent

Hits are evidence under a live agent row. Selecting a row navigates to that agent’s terminal.

Current API boundary. These are PuppeteerBridge and Godview main-process contracts. Agent and AgentRuntime currently expose no search method. The title “Aggregation API” groups this app capability; it does not name a new package or runtime service.
Owner Responsibility
Godview renderer Build live scope, query local facts, debounce text search, ignore stale responses and select a live agent.
Godview main Resolve the daemon, validate requests, negotiate reviewed protocol versions and normalize root-attributed hits.
External daemon / its host Own process lifetime, database, provider-native transcript reading, indexing and canonical session search.
Runtime / provider adapters Supply the live native session identity. Profile observation roots are available through the management API; passing them to an indexer remains app integration.

History bridge API

Godview exposes these methods on window.puppeteer and routes them through validated main-process IPC. All three are read operations.

PuppeteerBridge · excerpt

interface PuppeteerBridge {
  historyStatus(): Promise<HistorySearchStatus>;
  historyFacts(nativeSessionIds: string[]): Promise<HistorySessionFacts[]>;
  historySearch(request: HistorySearchRequest): Promise<HistorySearchResponse>;
}
Method Contract
historyStatus() Probes daemon liveness, reviewed protocol version and indexing readiness. A reachable daemon can still have an unusable index.
historyFacts() Looks up titles, summaries, cwd and canonical IDs by provider-native session ID. Returns cached facts when refresh fails within the same daemon/index generation; absent or unavailable entries are omitted.
historySearch() Searches indexed text and attributes hits to their navigable root. The response separately reports whether the query was answered and whether results may be incomplete.
Bridge method IPC channel
historyStatus() puppeteer:history-status
historyFacts(ids) puppeteer:history-facts
historySearch(request) puppeteer:history-search

Handlers accept calls from registered Godview windows. Invalid search requests return an unanswered result with diagnostic status; invalid facts requests return an empty list. The renderer calls IPC rather than the daemon directly.

Requests & results

These are the current bridge DTOs. Native and canonical identities have distinct meanings; keep them separate when joining results. 

interface HistorySearchRequest {
  query: string;
  /** Provider-native ids of the live runs to scope to; empty means everything the daemon knows. */
  nativeSessionIds: string[];
  /** Earliest live start, so a daemon without session scope narrows by time instead. */
  afterMs?: number;
  limit?: number;
  /** Widen word fragments; on by default where the daemon supports it. */
  prefix?: boolean;
}

interface HistorySearchResponse {
  status: HistorySearchStatus;
  /** False when the daemon had no answer; a sheet keeps what it last showed rather than saying "no matches". */
  answered: boolean;
  hits: HistorySearchHit[];
  /** The daemon clipped at its limit, so some sessions may be under-reported. */
  clipped: boolean;
}

interface HistorySearchHit {
  sessionId: string;
  rootSessionId: string;
  /** The root's provider-native id: the join key to a live run. */
  nativeSessionId?: string;
  title?: string;
  timelineId: string;
  /** `user` or `agent`; anything else is shown as itself. */
  kind: string;
  at?: number;
  /** Matches are marked with `[` and `]`. */
  snippet: string;
}

interface HistorySessionFacts {
  nativeSessionId: string;
  sessionId: string;
  rootSessionId: string;
  title?: string;
  summary?: string;
  cwd?: string;
  updatedAt: number;
  streamState: string;
}
Input / output Current behavior
query Normalized to one line, whitespace collapsed, trimmed and bounded to 512 characters before it reaches a URL.
nativeSessionIds At most 256 distinct opaque IDs after deduplication. Each ID is 1–256 characters and excludes whitespace, commas, slashes, backslashes and NUL. Invalid IDs reject the request.
Empty scope An empty array means all indexed sessions to the service. The Find UI still only builds/navigates rows from its supplied live agents.
afterMs Finite positive values are floored. Used as a time-bound fallback on protocol 17; modern scoped requests use canonical session IDs.
limit Default 300; supplied positive finite values are floored and capped at 1,000 by IPC validation. Legacy scoped search fetches up to 1,000 before filtering.
prefix Defaults to true where supported. Protocol 17 ignores it.
snippet Match markers are square brackets. Render as text/fragments, not raw HTML.
Times and kind Search hit at and fact updatedAt are numeric daemon timestamps; checkedAt is an ISO timestamp. kind is an opaque string, commonly user or agent.
clipped True when the daemon reaches the effective limit or root-resolution budget prevents full attribution. It is not a total-result count.

Identity joins & live scope

A search hit may belong to a delegated child. Navigation resolves that child to the root conversation, then finds a live run carrying the root’s native session ID.

Read the live native ID

Use AgentSessionInfo.nativeSession.id, falling back to monitor.session.nativeSessionId. Runtime run IDs and terminal IDs are not daemon lookup keys.

Resolve canonical session rows

Look up native IDs in the daemon. Retain its canonical session ID and rootSessionId.

Attribute matching children

Resolve a hit’s sessionId and root record as needed; nativeSessionId on the returned hit is the root’s provider-native ID.

Join to live agents

The Find model groups hits by nativeSessionId and builds one row for each live agent supplied by the shell. Selecting it invokes the normal monitor select action.

Identity Meaning
runtimeRunId Runtime-owned live run identity.
terminalSessionId Application terminal routing identity.
HistorySessionFacts.nativeSessionId Provider-native identity used to find that daemon session row.
HistorySearchHit.sessionId Daemon canonical ID for the session containing the matched text; may be a child.
HistorySearchHit.rootSessionId Daemon canonical root used for navigation attribution.
HistorySearchHit.nativeSessionId Root provider-native ID joined back to live agents; optional when attribution cannot be resolved.

The current bridge passes plain native-ID strings; it does not accept a provider/namespace field or a runtime epoch as part of the lookup key. The Find model deduplicates native IDs and uses the earliest known live start, minus five minutes, for legacy time scoping. A canonical ID must not be passed to runtime.agent().

Current navigation scope. This feature finds the live agents supplied to the sheet. It does not browse closed sessions or resume them from hits. Those operations would need a separate continuation and application navigation contract.

Readiness & failure semantics

A successful empty answer, a partial answer and an unanswered request are different states. The Find sheet preserves previous hits while it cannot obtain a reliable answer. 

type HistorySearchReadiness = 'ready' | 'building' | 'catching-up' | 'stale' | 'failed';

type HistoryOriginSource = 'setting' | 'environment' | 'announcement' | 'default';

interface HistorySearchStatus {
  origin?: string;
  source?: HistoryOriginSource;
  reachable: boolean;
  protocolVersion?: number;
  /** What this daemon generation can do; older ones are answered the long way. */
  capabilities?: { sessionScope: boolean; prefix: boolean };
  canonicalReady?: boolean;
  readiness?: HistorySearchReadiness;
  progress?: { done: number; total: number };
  /** One sentence for the sheet's foot when something is off. */
  detail?: string;
  checkedAt: string;
}
Condition Result / UI behavior
ready The search index can answer. Empty hits with answered: true are an actual empty result for the requested scope.
catching-up The current client accepts a consistent indexed snapshot while ingestion catches up. Display readiness/progress alongside results.
building, stale, failed Search is unanswered; retain previous hits and surface status.
Unavailable daemon, unsupported protocol, malformed payload, failed required lookup Search returns answered: false. No reliable answer must not be rendered as “no matches.”
Scoped native IDs have no indexed roots The client probes readiness before returning an empty answer. A ready canonical projection and answerable search index are required.
Origin/process/projection changes during the request Reject the mixed-generation answer; retry against the newly selected generation.
clipped: true Some sessions or hits may be under-represented. Retain visible results and show the limitation.

historyFacts() returns an array rather than an answered/stale envelope. Within the same daemon generation, it can return previously cached facts after a refresh failure; callers use historyStatus() for overall health. A disabled or absent service has no facts.

Main-process client contract

The injectable client is implemented in apps/godview/src/main/history-search.ts. It is an app module, not an export from the Puppeteer runtime package. 

function createHistorySearchService(
  options: HistorySearchServiceOptions,
): HistorySearchService;
interface HistorySearchServiceOptions {
  fetch: typeof fetch;
  /** Rechecked across awaits; one operation never mixes daemon generations. */
  origin(): ResolvedHistoryOrigin | undefined;
  now?: () => number;
  requestTimeoutMs?: number;
}

interface HistorySearchService {
  status(): Promise<HistorySearchStatus>;
  /** Title, summary, cwd, and canonical ids for live runs, by provider-native id. */
  facts(nativeSessionIds: readonly string[]): Promise<HistorySessionFacts[]>;
  search(request: HistorySearchRequest): Promise<HistorySearchResponse>;
}

interface ResolvedHistoryOrigin {
  origin: string;
  source: HistoryOriginSource;
  /** Distinguishes announced processes even when they reuse the same port. */
  generation?: string;
}

The origin() callback is rechecked across asynchronous work. Returning undefined disables history and drops the selected daemon context. The optional generation token distinguishes processes that reuse one origin. Inject fetch, clock and timeout for a host integration or deterministic tests. 

// Godview main-process integration; imports are app-local.
import { createHistorySearchService, resolveHistoryOrigin } from './history-search.js';

const history = createHistorySearchService({
  fetch: (input, init) => globalThis.fetch(input, init),
  origin: () => resolveHistoryOrigin({ announced: [] }),
});

const response = await history.search({
  query: 'retry handling',
  nativeSessionIds: ['native-session-id-from-a-live-agent'],
  limit: 100,
  prefix: true,
});
if (response.answered) {
  console.log(response.hits, response.clipped);
} else {
  console.log(response.status.detail ?? response.status.readiness);
}
Service versus IPC validation. The main-process service accepts typed input; the bridge handlers perform normalization and bounds checks on untrusted renderer input first. A new direct consumer should apply equivalent validation.

Daemon selection & configuration

Godview connects to an externally managed daemon. Its settings reader checks preferences on each operation; announcement discovery is cached for ten seconds.

Precedence Selection
1 · Setting Valid origin in history-search.json under Electron’s userData directory.
2 · Environment GODVIEW_HISTORY_DAEMON, when it is a valid loopback origin.
3 · Announcement Newest live compatible daemon announcement, with process identity retained for cache invalidation.
4 · Default http://127.0.0.1:4640. 
{
  "version": 1,
  "enabled": true,
  "origin": "http://127.0.0.1:4640"
}

Set enabled: false to disable history. The file is hand-edited: Godview reads it and never writes it. Missing, malformed, oversized or unrecognized settings use defaults. Valid origins are HTTP loopback origins using 127.0.0.1, localhost or [::1], with no non-root path, credentials, query or fragment. Redirects are rejected. 

interface HistoryOriginSources {
  configured?: string;
  environment?: string;
  announced: readonly HistoryAnnouncement[];
}

interface HistoryAnnouncement {
  origin: string;
  pid: number;
  protocolVersion: number;
  db: string;
  startedAt: number;
}

The announcement parser accepts wire schema rosetta-daemon/1, converting protocol_version and started_at into the fields above. ROSETTA_ANNOUNCE_DIR can select an absolute directory; defaults are ~/Library/Application Support/rosetta/daemons on macOS and $XDG_STATE_HOME/rosetta/daemons or ~/.local/state/rosetta/daemons otherwise.

Wire compatibility & bounds

The client accepts reviewed daemon protocols 17 through 20, identified by x-rosetta-protocol-version on responses. The table describes what this client consumes, not the daemon’s entire API.

Endpoint Consumed purpose
GET /api/status Protocol identity, canonical_ready, search readiness/progress, daemon start and projection epoch.
GET /api/sessions Canonical/native/root identity plus title, summary, cwd and stream state.
GET /api/search Normalized query q; canonical sessions and prefix on modern protocols, or after_ts on legacy protocol.
GET /api/sessions/:id Resolve an unfamiliar child/root session for search-hit attribution.
Protocol Behavior
17 Lists up to 1,000 recent sessions and filters native IDs locally. Scoped search uses after_ts and a 1,000-hit cap, then filters results in main. It does not perform modern delegated-child expansion or prefix matching.
18–20 Native-ID lookup uses chunks of 64. Search scopes with canonical root IDs and uses prefix matching. Child hits are resolved back to roots. Later wire additions do not change the fields consumed here.
Outside 17–20 Unanswered with diagnostic status until that protocol is reviewed.
Bound / cache Current value
HTTP request timeout 8 seconds by default; injectable on the service.
Known facts / confirmed misses 15 seconds / 3 seconds. Failed refreshes do not prove a miss.
Protocol identity reuse 60 seconds; explicit status probes still read the daemon.
Root/child lookups per search 32 uncached session lookups. Exhaustion can produce clipped results.
Generation invalidation Origin, announced process, reported daemon start, protocol version or projection epoch changes clear the session cache. Disabling history clears context.

Each operation stays with its selected daemon and index generation. A late response from a previous selection cannot populate the new context’s caches. Search results are bounded evidence, not an exhaustive history export.

Find sheet behavior

The UI combines local matching and daemon results without promoting search evidence into the live monitor.

Build the local facts lane

Match the query against title, summary, project, branch, model, provider, account, status and detail. Every query term must match some field.

Ask for indexed words

Debounce by 120 ms. Use the live native-ID scope, enable prefix matching and discard late responses to older queries.

Merge and rank

Group root-attributed hits into live rows, combine facts relevance, hit count and recency, and retain up to three displayed snippets per row.

Navigate

Selecting a row calls the existing select action. Without a reachable daemon, local facts matching remains available.

Live monitoring boundary. History titles and hits support navigation. They do not change agent.monitor, account quota, token burn rate, model identity or working/blocked state.
